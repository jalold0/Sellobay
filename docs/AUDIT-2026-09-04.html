Tekshirildi va toza chiqdi signal emas — dalil

Auditda «xato topilmadi» ham natija. Quyidagilar maxsus tekshirildi va to'g'ri ishlaydi — kelgusida qayta tekshirishga hojat yo'q.

  • Pul har doim Decimal. Schema'da barcha pul maydonlari Decimal(14,2); createOrder Prisma.Decimal bilan hisoblaydi. Hech qayerda float yo'q.
  • Klient narxiga ishonilmaydi. createOrder narxni bazadagi basePrice dan qayta hisoblaydi — narx bilan o'ynash mumkin emas.
  • Oversell himoyasi to'g'ri. Shartli UPDATE … WHERE quantityOnHand >= qty — Postgres qatorni lock qiladi, oxirgi donani ikki kishi olmaydi.
  • Bekor qilish/qaytarish atomik. Holat o'tishi updateMany + count === 0 tekshiruvi bilan — double-restock va double-refund oldini oladi.
  • Refresh token JWT emas. Opaque tasodifiy token, bazada SHA-256 hash bilan; rotatsiyada eskisi revoke qilinadi. Token turini almashtirish (type confusion) mumkin emas.
  • Sirlar kodda yo'q. Hardcode qilingan fallback topilmadi; requireEnv qo'riqlaydi.
  • Admin API rol tekshiruvi to'liq. 22 route tekshirildi; global/* route'lari server qatlamida assertOperator qiladi (route faylida ko'rinmaydi, lekin bor).
  • Katalog mock fallback'i dev'ga bog'langan. ALLOW_MOCK_FALLBACK production'da o'chiq — bo'sh baza bo'sh ro'yxat beradi, to'qima mahsulot emas.
  • Tip xavfsizligi kuchli. 16/16 typecheck; butun kod bazasida faqat 3 ta haqiqiy any; @ts-ignore yo'q.
  • i18n locale pariteti mukammal. uz/ru/en — 950 kalit, 0 farq.
  • Mehmon uchun chek yuklash himoyalangan. Auth yo'q, lekin rate-limit + yopiq saqlash + magic-byte tekshiruvi bor. Bu ataylab qilingan qaror, izohlangan.
  • Payme bekor qilishda loyalty qaytariladi. reverseOrderLoyalty tranzaksiya ichida chaqiriladi.
